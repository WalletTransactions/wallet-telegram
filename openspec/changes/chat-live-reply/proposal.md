# Proposal

## Why

Ответ чата бот показывает одним куском через 5–20 с после «Думаю…». wallet-ai и
гейтвей теперь отдают ход задания потоком событий
(`GET /api/ai/jobs/{id}/events`, changes `chat-sse-events` и `proxy-sse-stream`),
так что текст можно показывать по мере генерации.

## What Changes

- Пока задание `chat` выполняется, бот читает его события короткими окнами
  (около секунды за тик опроса) с `Last-Event-ID` и правит сообщение «Думаю…»:
  накопленный текст ответа, не чаще раза в 2 с (лимит Telegram на правки).
- Событие `tool` сбрасывает показанный черновик (текст перед вызовом
  инструмента не ответ) и ставит статус «Смотрю данные…» до появления ответа.
- Окно задаётся и серверу (`window_ms` у `/events`): слот потока освобождается
  сразу, а не по следующей записи.
- Итог по-прежнему берётся из `GET /api/ai/jobs/{id}`: подпись провайдера, обрезка,
  сбои и предел ожидания не меняются.
- Если потока нет (wallet-ai без `AI_STREAM_ENABLED`, старый гейтвей, 404/429,
  ошибка сети), бот работает как раньше, опросом статуса. 404 запоминается на
  время задания: к `/events` по нему больше не обращаемся.
- `TG_CHAT_STREAM_WINDOW_MS` (800); 0 выключает поток.

Вне объёма: web и Android, поток для `parse_expense`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `ai-chat`: пока ответ готовится, бот показывает текст по мере генерации;
  без потока поведение прежнее.

## Impact

- Код: `src/ai_client.*` (чтение событий, разбор SSE), `src/bot.*` (показ черновика
  в `process_pending_chat`), `src/main.cpp` (переменная), тесты, `README.md`.
- Нагрузка: каждый тик на каждое ожидающее задание открывает короткий поток к
  wallet-ai (лимит потоков на пользователя 3); тик удлиняется на окно.
- Зависит от wallet-ai (`AI_STREAM_ENABLED=true`) и гейтвея `proxy-sse-stream`;
  без них — прежний опрос.

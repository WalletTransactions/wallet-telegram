# Spec Delta

## Purpose

Команды, которыми подключённый пользователь смотрит состояние кошелька
(кошельки с балансами, категории, последние операции) и меняет свои настройки
в боте (кошелёк по умолчанию, часовой пояс), а также справка.

## ADDED Requirements

### Requirement: Данные — из wallet-report от имени пользователя
Команды чтения SHALL получать данные только из wallet-report токеном
пользователя. Прав на базу кошелька у бота нет. Если wallet-report ответил не
200, бот отвечает «Сервис временно недоступен, попробуйте чуть позже.».

#### Scenario: wallet-report недоступен
- **WHEN** wallet-report отвечает 500 на запрос `/wallets`
- **THEN** бот отвечает «Сервис временно недоступен…»

### Requirement: Справочник счетов
Справочником кошельков и категорий SHALL служить `GET /api/reports/accounts`:
живые неархивные счета; системные категории (`system_kind` ≠ 0, например
Transfer) отбрасываются; порядок — как в ответе. Справочник кешируется на
пользователя на 60 с; `/wallets` и `/categories` всегда читают его свежим и
обновляют кеш.

#### Scenario: Переименование на телефоне
- **WHEN** пользователь переименовал категорию в приложении и сразу отправил `/categories`
- **THEN** бот показывает новое имя

#### Scenario: Системные категории
- **WHEN** в леджере есть категория Transfer с `system_kind` = 1
- **THEN** она не показывается в `/categories` и не предлагается для траты

### Requirement: /wallets — кошельки с балансами
`/wallets` SHALL перечислить кошельки с балансом, включающим все операции по
сегодняшний день в поясе пользователя. Кошелёк по умолчанию отмечается «★»,
остальные «•». Сумма выводится в валюте кошелька с её точностью и символом.
Если кошелёк по умолчанию не выбран, в конце подсказка `/default <имя>`.

#### Scenario: Список с кошельком по умолчанию
- **WHEN** у пользователя два кошелька, и один выбран по умолчанию
- **THEN** бот отвечает «Кошельки:», где выбранный отмечен «★», а у каждого баланс вида «12 345,60 ₽»

#### Scenario: Кошельков нет
- **WHEN** у пользователя нет ни одного кошелька
- **THEN** бот отвечает «Кошельков пока нет — заведите их в приложении.»

#### Scenario: Баланс отсутствует в отчёте
- **WHEN** отчёт о балансах не содержит строки для одного из кошельков
- **THEN** у этого кошелька показывается 0

### Requirement: Валюта эквивалента отчётов
Для отчётов, требующих `eq_currency`, бот SHALL передавать валюту кошелька по
умолчанию, иначе — валюту первого кошелька. Итог в эквиваленте пользователю не
показывается.

#### Scenario: Кошелёк по умолчанию в евро
- **WHEN** кошелёк по умолчанию в EUR, а первый в списке — в RUB
- **THEN** запрос баланса уходит с `eq_currency=EUR`

### Requirement: /categories — категории
`/categories` SHALL перечислить категории пользователя (без системных) с их
количеством в заголовке.

#### Scenario: Есть категории
- **WHEN** у пользователя 3 категории
- **THEN** бот отвечает «Категории (3):» и по строке на категорию

#### Scenario: Категорий нет
- **WHEN** категорий нет
- **THEN** бот отвечает «Категорий пока нет — заведите их в приложении.»

### Requirement: /last — последние операции
`/last [N]` SHALL показать последние N операций по сегодняшний день в поясе
пользователя: 10 по умолчанию, значение ограничивается диапазоном 1–30.
Расход — «-сумма категория · кошелёк», доход — «+сумма категория → кошелёк»,
перевод — «сумма откуда → куда»; дата «ДД.ММ»; комментарий обрезается до 80 байт.

#### Scenario: Без аргумента
- **WHEN** пользователь отправляет `/last`
- **THEN** бот запрашивает и показывает не больше 10 операций под заголовком «Последние операции:»

#### Scenario: Слишком большое N
- **WHEN** пользователь отправляет `/last 100`
- **THEN** бот показывает не больше 30 операций

#### Scenario: Некорректный аргумент
- **WHEN** аргумент не число или длиннее трёх цифр, например `/last abc`
- **THEN** бот отвечает «Использование: /last или /last 20 (не больше 30).» и не обращается к wallet-report

#### Scenario: Операций нет
- **WHEN** у пользователя нет операций
- **THEN** бот отвечает «Операций пока нет.»

### Requirement: Сопоставление имён
Имя кошелька или категории из ввода SHALL сопоставляться без учёта регистра
(ASCII и кириллица), с `ё` = `е` и схлопнутыми пробелами: сначала точное
совпадение, затем уникальный префикс. Несколько префиксных совпадений — это
неоднозначность.

#### Scenario: Префикс и ё
- **WHEN** кошелёк называется «Тинькофф Ёлка», а пользователь пишет `/default тинькофф елк`
- **THEN** выбирается кошелёк «Тинькофф Ёлка»

### Requirement: /default — кошелёк по умолчанию
`/default <имя>` SHALL сделать найденный кошелёк кошельком по умолчанию для
трат. Без аргумента бот показывает текущий выбор и список кошельков. Если имя
неоднозначно, бот перечисляет подходящие кошельки; если не найдено — все
кошельки. В обоих случаях настройка не меняется.

#### Scenario: Однозначное имя
- **WHEN** пользователь отправляет `/default тинь`, и подходит только «Тинькофф»
- **THEN** бот сохраняет «Тинькофф» кошельком по умолчанию и отвечает «Кошелёк по умолчанию: Тинькофф.»

#### Scenario: Неоднозначное имя
- **WHEN** под `/default т` подходят «Тинькофф» и «Тбанк»
- **THEN** бот отвечает «Подходит несколько кошельков, уточните:» со списком обоих

#### Scenario: Без аргумента
- **WHEN** кошелёк по умолчанию не выбран, и пользователь отправляет `/default`
- **THEN** бот отвечает «Кошелёк по умолчанию не выбран.», подсказкой `/default <имя>` и списком кошельков

### Requirement: /tz — часовой пояс
`/tz <пояс>` SHALL принимать только имя пояса IANA, существующее в системной
tzdata, сохранять его и отвечать текущими датой и временем в этом поясе. Без
аргумента бот показывает текущий пояс и время в нём. Пояс определяет «сегодня»
для трат и отчётов.

#### Scenario: Корректный пояс
- **WHEN** пользователь отправляет `/tz Asia/Tbilisi`
- **THEN** пояс сохранён, бот отвечает «Часовой пояс: Asia/Tbilisi. Сейчас там ДД.ММ, ЧЧ:ММ.»

#### Scenario: Неизвестный пояс
- **WHEN** пользователь отправляет `/tz Mars/Base`
- **THEN** бот отвечает «Не знаю пояса «Mars/Base».» с примерами, и настройка не меняется

### Requirement: /help — справка
`/help` SHALL описывать строгий формат траты с примерами и перечислять команды.
Строка про ввод свободным текстом добавляется, только если пользователь
подключён и wallet-ai сообщает, что ИИ включён; ответ об этом кешируется на
60 с. Не удалось узнать — строки нет.

#### Scenario: ИИ выключен
- **WHEN** `WALLET_AI_URL` не задан
- **THEN** справка не упоминает ввод свободным текстом

#### Scenario: ИИ включён
- **WHEN** подключённый пользователь отправляет `/help`, а `GET /api/ai/status` отвечает `enabled: true`
- **THEN** справка содержит строку «Можно и своими словами: «кофе 200», …»

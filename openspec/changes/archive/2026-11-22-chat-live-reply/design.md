# Design

## Context

См. proposal.md. Бот однопоточный: цикл `getUpdates` (1 с при ожидающих
заданиях) и `ai_tick()`, который опрашивает `get_job` каждого ожидающего.
Держать долгое SSE-соединение в этом потоке нельзя: оно остановило бы приём
апдейтов и опрос остальных заданий. Правки в других сервисах не нужны:
wallet-ai (`chat-sse-events`) и гейтвей (`proxy-sse-stream`) уже выкачены.

## Goals / Non-Goals

**Goals:** текст ответа появляется в сообщении по мере генерации; без потока
всё работает как раньше.

**Non-Goals:** отдельный поток под каждое задание; поток для `parse_expense`;
правки чаще лимита Telegram.

## Decisions

### D1. Короткие окна с `Last-Event-ID` вместо долгого соединения
Каждый тик бот открывает `/events` с `Last-Event-ID` на `TG_CHAT_STREAM_WINDOW_MS`
(800 мс), собирает пришедшее, закрывает соединение и продолжает с последнего
`id` на следующем тике. Это тот же приём, что у переподключения: журнал
wallet-ai хранит события, поэтому пропусков нет, а поток закрывается сам при
`done`/`error`. Альтернатива — отдельный поток на задание: сложнее
синхронизация с отправкой в Telegram, и бот перестал бы быть однопоточным.
Цена: тик удлиняется на окно на каждое ожидающее задание; при нескольких
одновременных вопросах опрос замедляется (допустимо для личного бота).

### D2. Итог — из `GET /api/ai/jobs/{id}`
События нужны только для показа черновика. Как только в окне пришёл `done` или
`error` (или события кончились и задание завершилось), бот идёт по прежнему
пути `get_job`: подпись, обрезка, сбои, предел ожидания не дублируются.

### D3. Правки сообщения
Текст = склейка `delta` после последнего `tool`; правка не чаще раза в 2 с, и
только если текст изменился (Telegram отвечает ошибкой на правку без
изменений). Текст обрезается по пределу сообщения. Показ идёт простым текстом,
как итог.

### D4. Запасной путь
404/429 на `/events` или сбой сети: бот на этом тике опрашивает статус как
раньше; 404 запоминается на время задания (один лишний запрос на задание при
выключенном потоке, глобального таймера нет: 404 означает ещё и «задание
истекло», а это решает `get_job`). Это и есть миграция: бота можно выкатывать до
включения `AI_STREAM_ENABLED`.

### D5. Приватность
Тексты событий в журнал бота не пишутся; в метриках только исход чтения
(`ok`, `disabled`, `busy`, `error`).

## Risks / Trade-offs

- [Каждое окно держит слот потока wallet-ai ≤ 1 с] → лимит на пользователя 3 больше одного задания; 429 уходит в запасной путь.
- [Лимит правок Telegram] → не чаще раза в 2 с.
- [Длинный тик при нескольких заданиях] → окно короткое; `TG_CHAT_STREAM_WINDOW_MS=0` выключает поток.

## Migration Plan

Выкатить бот; потока нет — прежнее поведение. Включить `AI_STREAM_ENABLED=true`
в wallet-ai — бот сам начнёт показывать черновик. Откат: `TG_CHAT_STREAM_WINDOW_MS=0`.

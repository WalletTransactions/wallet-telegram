# Design

## Context

- `Bot::handle` маршрутизирует по порядку: callback → только личные чаты →
  allowlist → `/start`, `/help` → команды со связкой → строгая трата
  (`looks_like_expense`) → свободный текст с цифрой (`ai_eligible`) →
  непонятое.
- Задания wallet-ai бот создаёт в `try_ai` и опрашивает в `ai_tick` /
  `process_pending_ai` (`PendingAi` с `fallback`, предел 90 с). Токен
  берётся `with_token` на каждое создание (300 с).
- Кнопки карточки траты кодируются `callback::make/parse` (строгий разбор,
  `draft_id`).
- Бот однопоточный (HTTP-клиент Telegram, база, черновики), всё состояние
  ожиданий — в памяти.
- Требования — `specs/ai-chat`, `specs/ai-provider-choice` и три
  MODIFIED-дельты.

## Goals / Non-Goals

**Goals:**
- Вопросы не ломают существующий ввод трат: «няня 3000» и «кофе 200» идут
  прежним путём.
- Один механизм ожидания для `parse_expense` и `chat`.
- Детерминированная, тестируемая маршрутизация без вызова модели.

**Non-Goals:**
- Классификация «вопрос или трата» моделью (лишний вызов GPU на каждое
  сообщение).
- Хранение диалога в базе бота. История живёт в wallet-ai, бот хранит только
  `conversation_id`.

## Decisions

### D1. Эвристика вопроса — чистая функция
`chat_routing::looks_like_question(text)`:
- обрезка пробелов, нижний регистр, `ё` → `е`;
- первое слово до пробела или знака препинания;
- проверка по списку из спеки или «?» в конце.

Длина — до 1000 байт, как `input.text` у wallet-ai. Список намеренно
короткий: ложное «вопрос» для траты хуже, чем лишний шаг через
`not_expense` (D3). Слова вроде «потратил» в список не входят: «потратил
300 на кофе» — трата.

### D2. Порядок маршрутизации
Новые ветки встают **после** строгой траты и **до** свободного текста:
```
команда -> строгая трата -> [ИИ + связка]
                             ответ на уточнение? -> chat
                             вопрос?             -> chat
                             цифра, <=300 байт?  -> parse_expense
                          -> непонятое
```
Ответ на уточнение проверяется первым. «Сентябрь» после «За какой месяц?»
не похож ни на вопрос, ни на трату, но должен попасть в тот же диалог.

### D3. `not_expense` → chat в том же сообщении
`process_pending_ai` при `not_expense` и `fallback.kind == NotUnderstood`
создаёт задание `chat` с тем же текстом и ключом `tg:<id>:<update_id>:chat`,
правит «Разбираю…» в «Думаю…» и переиспользует тот же `message_id`. Цена —
два вызова модели на такой текст (до 10–20 с на GTX 1070). Это редкий путь:
большинство вопросов ловит D1.

### D4. Ожидание: `PendingAi` с видом
`PendingAi.kind ∈ {parse_expense, chat}` и свой предел: 90 с и
`TG_CHAT_WAIT_SECS` (150). У wallet-ai дедлайн `chat` 120 с, плюс очередь.
Обработка итога разветвляется по виду. Для `chat` — показ текста с подписью
провайдера (спека «Показ ответа») или текст сбоя. Отмена по пределу — тот
же `DELETE`.

### D5. Состояние диалога — в памяти бота
`ChatState { conversation_seq; last_question_at; awaiting_reply_until }` по
`tg_user_id`.
- `conversation_id = "tg-<tg_user_id>-<seq>"`.
- `seq` растёт на `/new` и после 1800 с без вопросов. TTL совпадает с
  историей wallet-ai.
- `awaiting_reply_until = now + 600`, если `result.text` закончился «?».

После рестарта бот начинает с нового `seq`: стартует от времени процесса, а
не от нуля, чтобы не попасть в старую историю wallet-ai.

### D6. `/ai` и согласие — отдельный разбор кнопок
`callback_data` с префиксом `ai:` разбирает `callback::parse_ai`.
- Провайдер — только `[a-z]{1,16}`, сравнивается со списком из `GET
  /api/ai/settings`.
- Ветка в `handle_callback` до разбора кнопок черновика.
- Экран `/ai` и экран согласия — правка того же сообщения (`edit_message` с
  клавиатурой).
- Текст согласия — константа бота, а не ответ wallet-ai: он должен быть
  виден, даже если wallet-ai вернул неожиданный `title`.

### D7. `AiApi`
Новые методы:
- `create_chat(token, input, key)` → тот же `CreateResult`, плюс статус
  `ProviderUnavailable` для 503 `provider_unavailable`;
- `get_settings(token)` → `optional<json>`;
- `put_settings(token, body)` → `{status, json}`.

Разбор ответов — чистые функции, как `parse_create_response`.

### Правки в других сервисах
- **wallet-ai:** `add-chat-agent` (`kind: chat`, `/api/ai/settings`,
  503 `provider_unavailable`).
- **google-auth, wallet-gateway, wallet-infra:** без правок. Токен бота уже
  содержит `ai:use` и `aud` `wallet-ai`.

## Risks / Trade-offs

- [Эвристика пропустит вопрос без вопросительного слова и «?»: «траты на
  такси за неделю»] → при цифре он уйдёт в `parse_expense`, а затем
  `not_expense` → chat (D3). Без цифры ответ «Пока не понимаю…», и `/help`
  подсказывает формат вопроса.
- [Эвристика примет трату за вопрос: «что-то 300»] → «что» в списке, но
  первое слово здесь «что-то», и оно не совпадает. Список проверяется
  тестами на реальных примерах из `/last`.
- [Подпись провайдера раскрывает, что ответ дал Claude] → это и нужно:
  пользователь видит, куда ушли данные.
- [Окно уточнения ловит обычную трату «кофе 200» после вопроса модели] →
  окно 600 с и только после ответа с «?». Трата строгого формата
  («200 кофе») идёт прежним путём.

## Migration Plan

1. Выкатить после wallet-ai `add-chat-agent`. До этого wallet-ai отвечает 400
   «неизвестный kind: chat» → бот считает задание не созданным и даёт
   запасной ответ («ИИ не смог ответить…»).
2. Откат — предыдущий образ. Состояние в памяти, миграций нет.

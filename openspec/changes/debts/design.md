# Design

## Context

Бот получает справочник кошельков и категорий одним запросом
`GET /api/reports/accounts` и кеширует на 60 с (`wallet-read-commands`).
Системные категории отбрасываются там же, по `system_kind`. Запись бот
ведёт create-only через push wallet-api; кошелёк для траты берёт из этого
справочника.

## Decisions

### D1. Фильтр — там же, где системные категории

Долговой кошелёк (`counterparty_uuid` не `null`) отбрасывается при разборе
ответа `/accounts`, до кеширования. Тогда `/wallets`, выбор кошелька при
вводе траты, `/default` и сопоставление имён (`Сопоставление имён`) видят
одно и то же множество, а отдельных проверок по месту использования нет.

*Альтернатива:* фильтровать в каждой команде. Отклонено: забытая команда
дала бы трату с долгового кошелька.

### D2. Отсутствие поля = не долговой

Совместимость с wallet-report, который ещё не выкатил `counterparty_uuid`:
поле читается необязательным.

### D3. Нужна ли правка в других сервисах

wallet-report (поле в `/accounts`) — парный change. wallet-api, wallet-ai,
wallet-gateway не затрагиваются. Если wallet-ai получает список кошельков
сам, а не от бота, проверить это на реализации (задача 1.2).

## Risks / Trade-offs

- [Пользователь не видит долговой кошелёк в боте] → так и задумано: долги
  ведёт Android; бот их не умеет.
- [Кошелёк по умолчанию был долговым] → кошельки по умолчанию выбираются из
  отфильтрованного списка; сохранённый `default_wallet` долгового кошелька
  сбрасывается так же, как удалённый (поведение существующего `/default`).

## Migration Plan

Выкат после wallet-report. Откат — предыдущим тегом.
